# 經驗

執行時之累積經驗,留給後續嘗試、執行與判斷.新條續號.

1. **專案根不能以套件檔之位置推導.** 抽提前程式放在專案之 `lib/`,以 `import.meta.url` 往上一層即專案根;搬進套件後同一寫法會指到 `node_modules/<套件>/`,設定讀不到、輸出落在套件夾.改為由進入檔把自身之資料夾寫入環境變數(子行程繼承),套件只讀該變數;進入檔須以動態匯入載入套件之程式(靜態匯入先於任何敘述執行,來不及設定).
2. **搬動程式夾會讓「禁區」規則失效而不報錯.** 操作掃描以路徑樣式判斷 agent 有無讀取迴圈驗證之程式;樣式寫死 `lib/domain` 時,套件安裝後之實際位置 `node_modules/<套件>/src/domain` 完全不中 —— 測試照樣全綠(測試案例也寫舊路徑).搬動後須以新配置之實際路徑各寫一組案例(讀單檔、列目錄、遞迴搜尋、萬用字元),並確認「指名之其他檔不列」仍成立.
3. **禁區字樣不得寫死使用端之名稱.** 原規則以策略庫專案之資料夾名比對;抽提後改由設定推得(策略庫位於專案夾外時取其所在之資料夾名,末段為 `data` 等通用名者取上一層),另開 `settings.guard.forbidden` 供專案自行追加.
4. **「執行即動作」之指令稿不必改寫成函數.** 命令列程式原為頂層指令稿(含頂層 `await` 與 `process.exit`);以「進入檔設定環境變數 → 動態匯入指令稿」即可原樣沿用,行為與抽提前相同,回歸風險最小.
5. **合約含專案自己之數值.** 各期間之日期、求解窗、標的與策略庫之規模寫在合約內供 agent 閱讀;套件只給參考版,專案之合約不覆寫,升版時以並列之參考版人工比對併入.
6. **擴充診斷之新增不追溯.** 新診斷只對其後之完整評估生效;要讓既有成品也有值,須以同一評估器重放並核對選集指紋後併入,不可由其他診斷之輸出推算後手填(日後改算法時無從核對).
7. **持倉上限擋單時,同一進場棒之訊號次序是績效之雜訊來源.** 下單率低之成品只換此次序,分數即可變動一成以上;比較兩個版本前先量此帶寬(擴充診斷之 `simulate` 之 `orderSalt`).
8. **去識別之測試不得列名單.** 把使用端之名稱寫成斷言(`!/某名/.test(s)`)本身就把名稱寫進公開庫.改為通則檢查(磁碟機路徑、家目錄路徑、本機家目錄、私有網段位址),並以「執行時組出」之正反例驗檢查本身(本檔原文不含真實痕跡),另斷言掃描範圍含代表檔(掃描回空不算通過).
9. **「只改註解」要以去註解之 token 比對驗證,且須含換行位置.** 刪除行尾註解時連換行一起刪,兩列併成一列:token 序列不變,但自動補分號失效而成語法錯誤(`node --check` 才抓得到).比對時每個 token 另記「與前一 token 之間有無換行」.
10. **以正規式去註解再掃程式碼時,字串內之 `//` 會被誤當註解.** `'file:///…'` 之 `//` 起至行尾被刪,同列之 `windowsHide: true` 跟著消失 → 守門誤判.掃選項之守門只認行首或空白之後之 `//`;驗守門時做「拿掉某一處」之變異,且失敗訊息須指出行號,確認紅的是那一處而不是別處.
11. **UMD 打包檔內 `import.meta.url` 指向打包檔本身.** 以「本檔往上 N 層」定位套件檔者(`initProject` 之套件夾、`makeTexts` 之程式夾)於 `dist/` 內失準;呼叫時才錯,載入不錯.命令列程式與這兩者一律以 ESM 深層路徑取用.
12. **以「規格(臂 + 起點)」去重之處,另一種機制掛在同一組寬臂之下會被靜默略過.** 做夢排方向時無從得知樹上已有同規格之節點,方向入前緣時才發現相撞;只回 `ok: false` 而不上報,下一輪即少一個節點(只在輪末摘要之「入前緣 N」可看出差)。處置:相撞之探索類改帶區分用之鍵(依據文字之雜湊;沿用主張鍵之欄位與對應機制)入前緣,依據相同才略過;任何「未入前緣」者由輪末摘要明列。**前緣內已有同臂同起點而未執行之提案**不改帶鍵(重寫依據文字之同一方向會變成兩個節點),維持略過並列出。帶鍵之探索方向會流入所有消費「鍵」之處(前次方向回顧之範本、命令列列示、共同儲存區之欄位),盤點時以 `spec.claim|claimKey` 全集逐站核對,不假定「有鍵 = 驗證類」。
    **外審補格(同案):** ①「相撞才帶鍵」會讓**已執行之探索逐字重提**多跑一次(修前為略過):相撞時須先看既有節點本身是否出自同一依據(節點文件 `task.direction.rationale`),且同一依據之鍵之規格已有節點(含帶鍵之方向改掛後)者不論不帶鍵之規格是否被占用皆略過 ②摘要寫「由前緣內既有之提案執行」是過度承諾:前緣內之同規格可能已是 `rejectedByGate`,須在原因註明該項狀態,摘要不承諾 ③組成回顧範本之識別文字依**方向類型**,不依有無 `claim` 欄(探索類可能殘留範本佔位之 claim) ④輪末摘要之單行清單會被一頁摘要截 400 字,改一條一行 ⑤掃描範圍之排除名單不帶斜線者比對任一路徑段,須以前導 `/` 錨定於包根 ⑥任務書內另有寫死之 `src/eval/`、`src/arsi/`,與 `lib/` 同類,一併由所在推得.
13. **輪末鉤子內之一行(組句)抽成純函數才測得到.** `afterRound` 需派做夢、起子行程、讀帳本,套件內無整輪測試;把「方向未入前緣」與「前次方向之一條」抽成純函數(`unproposedNoteOf`、`prevDirectionOf`,比照 `outwardNoteOf`)即可單元測;鉤子內之呼叫站點仍只能由整輪回歸觸及(列於 state 之缺口)。
14. **讀 `.gitignore` 之測試在 npm 包內必壞.** npm 預設不收 `.gitignore`,包內亦無 `.git`:以 `.gitignore` 定範圍或檢查列項者在包內讀檔拋 ENOENT.判別「包內」= 既無 `.git` 亦無 `.gitignore`(缺其一不算,免得 repo 內缺檔被當成包內而放寬);包內之掃描範圍 = 全部文字檔(不含 `node_modules` 與測試暫存夾).驗證法:`npm pack` 解開於 `./tmp/`(祖先目錄之 `node_modules` 可解析相依,不必連結),以設定 cwd 之小腳本跑 mocha;另以「有 `.git` 夾而無 `.gitignore`」之副本確認仍失敗。
15. **外部序列(`ctx.series`)之無前視靠三個約定同時成立,缺一即前視.** ①時間標記 = 棒之開盤時間,且值視為於該棒收盤時已得知(與因子同一約定;進場價為該棒收盤價)②`ctx.series` 之切片終點 = 決策棒(不含)③帳本於 `endTime` 截斷,時間 ≥ 終點之列對不到棒而丟棄.其中①是使用端之責任、評估器無從檢查(量若在標記之棒收盤後才得知,須由使用端標在其後之棒),故必須寫入合約而非只寫在程式註解.測試不比對 `slice` 之寫法,改用「序列之值 = 其棒序號」之夾具,使無前視變成可直接斷言之式子(回傳之最大值 = 決策棒 − 1、全部 < 決策棒);把範圍改為含決策棒之變異即被擋下.
16. **外部資料之值不可用 `Number(x)` 一概轉型.** 空白字串、`[]`、`true`、`10n` 都會轉成有限數(0、1、10)而靜默成為資料;對位函數只收數字與非空白之數字字串,其餘當缺值(`NaN`);同一時間重複者以最後一個有效值為準(無效列視為未列).檔名不合、內容非陣列、時間格式與 K 線不同(一個值也對不到)各有明確之拋錯或記錄,不靜默變成全 `NaN`.
17. **選配欄之「有名稱而無檔」要有雙向之一致性.** 帳本記 `meta.seriesNames` 而 `ser.f64` 缺或長度不符 ⇒ `ctx.series` 拋「請重建帳本」;重建於同一資料夾而不再給序列 ⇒ 須移除舊之 `ser.f64`(否則名稱與欄不符).命令列之測試其工作目錄須刻意不是專案根,才驗得到「相對路徑以專案根解析」(工作目錄即專案根時,漏掉 `P()` 之變異不會被抓到).
18. **變異驗證可把 `src` 與 `test` 複製於 `./tmp/<名>/mut/<編號>/`.** 裸匯入自動向上解析到專案之 `node_modules`,不必目錄連結;每個變異以單一字串替換(須恰出現 1 次)套於副本,以 `mocha --reporter json` 取失敗案名;37 處約 3.5 分鐘.**新增之規則可能掩蓋舊測試之變異**:對位加入「同一時間相異值取缺值」後,把多個無效值塞在同一時間之舊測試,其誤收之值會與他值互相矛盾而被取缺值,放寬值轉型之變異竟存活;改為每個無效值單獨對位後才又被擋下 —— 改規則後須重跑全部變異,不只新增者.
